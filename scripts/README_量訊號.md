# 量訊號工具組（2026-08-01 建）

解決一個具體問題：**判斷記憶體的獲利成長是「需求真的起來」還是「純粹漲價」，但不想等到 MU 財報才知道。**

MU FQ3-2026 揭露的量價拆解是關鍵起點：DRAM 位元出貨量 QoQ 只有低個位數，ASP 卻漲了 60 幾 %，
營收 QoQ +67% 裡價格佔了約 95%。要確認這是不是全行業現象、以及有沒有在改變，
需要比季報更快的訊號。以下兩個工具就是為此建的。

---

## 1. `fetch_korea_exports.py` — 韓國海關旬報（自動，已掛統一更新 Step 4.5）

**為什麼**：韓國佔全球 DRAM 約七成，半導體出口是頻率最高的需求總量代理。

**公布節奏**：每月 **11 日**出 1~10 日、**21 日**出 1~20 日、**次月 1 日**出全月。
比台系月營收（每月 10 日）早、比 MU 財報（季）早得多。

**資料源與逆向過程**（站方改版時照這個重做）：
1. 站點 `tradedata.go.kr` / `unipass.customs.go.kr/ets/` 是同一個 SPA，直接 curl 只拿到殼。
2. 用 playwright 攔 XHR，在首頁找到旬報選單：`ets_f_prccMenuLoad('/cts/hmpg/openETS0100173Q.do', {menuId:'ETS_MNK_10500000'})`。
3. 該頁載入的 JS `/cts/js/ets/hmpg/trade/ETS0100173Q.js` 裡有全部答案：
   - 查詢端點 `POST /cts/hmpg/retrieveTentativeValues.do`
   - 參數 `statsKind / imexTpcd / priodKind / priodFr / priodTo / priodDate / selectPaging / showPagingLine`
   - 欄位對照在 `f_tableDownData()`：**出口×品項別口徑下 `itemUsdAmt01` 固定是半導體**
4. **免金鑰、免註冊**，只要先 GET 首頁拿 JSESSIONID cookie 再 POST 即可。
   （data.go.kr 上那個官方 OpenAPI 需要申請金鑰，本路徑不需要。）

**單位**：千美元。**口徑雷**：韓國「半導體」含記憶體＋系統半導體＋代工，**不是純記憶體**，
只能看總量方向與 YoY 轉折，不能當 bit shipment 的精確替代。

**驗證**：2026-07 1~10 日半導體出口 11,207 百萬美元、YoY +193.0%，與韓媒同期報導完全吻合。

**輸出**：`data/korea_exports.json`（含 total / semiconductor / YoY / 半導體佔總出口比重）。

## 2. `log_memory_guidance.py` — 三雄 bit 指引記錄簿（手動，財報日用）

**為什麼**：位元出貨量只出現在法說會，沒有 API。而 **SK hynix 與三星的財報比 MU 早約兩個月**——
先記下他們的下季指引，等於提前兩個月知道 MU 會說什麼。

```
python scripts/log_memory_guidance.py              # 看對照表
python scripts/log_memory_guidance.py --interactive # 財報日新增一筆
```

資料檔 `data/memory_guidance.json` 是純 JSON，也可直接手動編輯。

**★口徑雷**：三家財季錯開——MU 財年 8 月底結束，季度比 hynix/三星的日曆季**早一個月**
（MU FQ3 = 3~5 月，hynix Q2 = 4~6 月）。跨公司比 QoQ 必須用 `period_end` 對齊期間，
不能用季度標籤，否則會把不同月份的價格波段疊在一起比。

**已建檔的種子資料**：
| 公司 | 期間結束 | DRAM 量 QoQ | DRAM ASP QoQ | 下季 DRAM 量指引 | NAND 量 QoQ | 下季 NAND 量指引 |
|---|---|---|---|---|---|---|
| Micron FY26Q3 | 2026-05-28 | 低個位數 % | +60 幾 % | （未記錄） | 中個位數 % | （未記錄） |
| SK hynix 2026Q2 | 2026-06-30 | 高個位數 % | 約 +30% | **約 +10%（加速）** | 中十幾 % | **低個位數 %（急鈍化）** |

**目前的判讀**：DRAM 量在加速、NAND 量在熄火。AI 端獨撐，消費端沒回來。
這對以 DRAM 為主的 MU（DRAM 佔營收 76%）有利，對純 NAND 的 SNDK 不利。

## 3. `calc_bit_proxy.py` — 台系量代理（自動，已掛統一更新 Step 8.92）

**恆等式，不是模型**：

```
美元營收MoM = (1 + 台幣營收MoM) / (1 + USDTWD月均MoM) - 1
量MoM      = (1 + 美元營收MoM) / (1 + 合約價MoM) - 1
```

**匯率那一步不可省**：月營收是新台幣、DRAM 報價是美元。2026 台幣走貶，
不修正會讓台幣營收虛高、推出來的量**被高估**（實際萎縮比看到的更嚴重）。

**匯率源**：Yahoo chart API `USDTWD=X` **日線自算月均**（`query1.finance.yahoo.com/v8/finance/chart/`，免金鑰）。
- 為何用日線自算而非月線：月線端點會回**重複的時間戳**（實測 2026-03 出現兩筆），日均較可靠。
- **FRED DEXTAUS 實測持續 read timeout（25s／40s 都失敗），本機環境不可用**，別再試。
- 與既有專案一致：`portfolio_analyzer.py`、盤前分析師都用 `USDTWD=X`，只是它們抓即時值、這裡要歷史月均。
- 快取在 `data/fx_usdtwd.json`（數值＝1 美元兌新台幣，**上升＝台幣貶值**）。

**跨 venv 執行**：本腳本需 pandas/pyarrow 讀月營收 parquet，
**記憶體儀表板 venv 沒有這兩個套件**，故借月營收追蹤器的 venv 跑，工作目錄仍設在本專案：
```
& 'C:\Users\USER\Claude\Projects\台股策略\月營收追蹤_monthly-revenue-tracker\venv\Scripts\python.exe' scripts\calc_bit_proxy.py
```

**首次實測（2026-05→06，匯率修正後）**：

| 公司 | 台幣營收MoM | 匯率MoM | 美元營收MoM | 合約價MoM | **→ 量MoM** | 口徑 |
|---|---|---|---|---|---|---|
| 南亞科 2408 | +6.2% | +0.45% | +5.7% | +15.3% | **−8.3%** | DDR4 |
| 南亞科 2408 | +6.2% | +0.45% | +5.7% | +8.6% | **−2.6%** | DDR5 |
| 華邦電 2344 | +3.0% | +0.45% | +2.5% | +15.3% | **−11.1%** | DDR4 |
| 華邦電 2344 | +3.0% | +0.45% | +2.5% | +8.6% | **−5.6%** | DDR5 |

修正前後差約 0.4pp（5→6 月台幣只貶 0.45%），但 **6→7 月台幣貶 1.75%**（31.6379→32.1922），
下一期修正的影響會明顯放大——這正是為什麼要接。

輸出 `data/bit_proxy.json`，並在終端附上韓國旬報與三雄 bit 指引當對照，三個訊號並排看。

## 判讀規則（三者交叉才算確認）

| 訊號 | 頻率 | 看什麼 |
|---|---|---|
| DRAM/NAND 現貨價 | 每日（既有） | 現貨領先合約約 1~2 個月，先轉弱的是現貨 |
| **韓國旬報半導體出口** | **每 10 天（新增）** | YoY 的**加速度**，不是絕對值；月間絕對值有工作天數差 |
| **台系量代理**（`calc_bit_proxy.py`） | 每月 10 日 | 營收÷價格÷匯率＝量，但代理的是**利基/消費端**不是 AI 端 |
| **三雄 bit 指引** | **每季（新增）** | 最直接。hynix/三星領先 MU 約兩個月 |

**分岔本身就是訊號**：台系（南亞科、華邦電做利基型/DDR4）反推的量在萎縮，
韓系（伺服器/HBM）的量在加速——兩條線的距離拉大＝這波由 AI 獨撐，消費端仍未回溫。
